F7 / F10a Bug-fix Sweep — 2026-10-27
====================================

Context: F3 + F7 + F10a were combined on feat/f3. A review of the combined tree
found the bugs below; all are fixed. Written to keep the branch compatible
before F4 and F9 are merged in.

## High — functional

1. Donor inbox never showed pending notifications.
   - worker/src/notify.js created `notifications` docs without `sentAt`;
     web/src/pages/donor/Alerts.jsx orders by `sentAt`, and Firestore omits
     documents missing an orderBy field. With email disabled, sentAt was never
     written, so the inbox stayed empty forever.
   - Fix: write `sentAt: null` explicitly at create.
   - Also removed dead code in notifyNewMatches (a filter that was always true).

2. Worker CORS blocked the deployed site.
   - worker/wrangler.toml ALLOWED_ORIGINS was `http://localhost:5173` only, so
     the preflight from https://dugo-plus.web.app failed: /match fell back to
     cron silently and the F10 audit screen errored.
   - Fix: ALLOWED_ORIGINS now includes https://dugo-plus.web.app and
     https://dugo-plus.firebaseapp.com.
   - EXTERNAL: needs `npm run worker:deploy` for it to take effect.

3. F10a privilege escalation.
   - The Worker's admin-only audit routes gate on the client-written
     `users.role === 'admin'`, and the `users` create rule let a client set its
     own role to `admin`. Any account could self-declare admin and read/append
     the audit chain.
   - Fix: firestore.rules `users` create is donor-only for self-create (D29; F9 owns D26);
     only an admin claim (or console/Admin SDK) may create hospital/admin.
   - EXTERNAL: needs `firebase deploy --only firestore:rules` for production.

## Medium

4. Donor `/donor/alerts` rendered the admin `AppShell` (donor saw the admin nav).
   - Fix: rewrote pages/donor/Alerts.jsx on the donor `.pub` chrome (pub-nav),
     matching Profile; added app.css `.alerts-*` rules. Also restyled from the
     previously unstyled `donor-alerts__*` classes.

5. Doc drift: F7 writes `bloodRequests.matching` but the schema did not record it.
   - Fix: schema §2.4 field + note, and a SCHEMA_CHANGELOG entry.

6. Audit append was untransactional (read sequence, then write) — concurrent
   appends could fork the chain.
   - Fix: worker/src/audit.js appends inside one Firestore transaction, reading
     a reserved `auditBlocks/_meta` head doc to serialize. Added
     beginTransaction / getDocumentInTransaction / runQueryInTransaction /
     commitWrites to worker/src/firestore.js. Schema §2.13 + changelog updated.

## Low / cosmetic

7. web/src/pages/admin/AuditTrail.jsx used `var(--danger)` (undefined → now
   `--d-red`), `.muted` on the verify summary (that class uppercases text → now
   inline `--d-muted`), and `data-status="warn"` (undefined tone → `warning`).

### Deployment fix (403 PERMISSION_DENIED)

Symptom: clicking Verify Chain returned
  Firestore request failed: 403 { "error": { "code": 403, "message": "Missing or insufficient permissions.", "status": "PERMISSION_DENIED" } }

Cause: the message is produced by the Worker (worker/src/firestore.js), not the
browser. The Worker reaches Firestore as the service account
firebase-adminsdk-fbsvc@dugo-plus, which bypasses firestore.rules. Newer Firebase
projects create that account without Firestore (datastore) access, so the OAuth
token exchange succeeds but Firestore rejects every call. F7 /match was affected
the same way.

Fix:
- Granted the service account roles/datastore.user in GCP IAM
- Rotated the service-account key (the previous key was exposed)
- Updated the Worker secret: wrangler secret put FIREBASE_SERVICE_ACCOUNT

Verified: Verify Chain -> "Chain Verification (valid) - Blocks verified: 0 -
Empty chain" (deployment f4ee0c83, 2026-10-24T14:26:53Z)

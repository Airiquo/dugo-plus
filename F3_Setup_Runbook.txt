F3 Setup Runbook
================

For: seeding the dev facility and creating the hospital login that F3 needs.
Audience: the repo owner. Everything here is terminal work; no app code changes.

Why this is needed
------------------
The F3 hospital screens only work when two things exist in Firestore:
  1. a facility document, `hospitals/tagaytay-blood-bank`
  2. a hospital account, `users/{uid}` with `role: "hospital"` and that
     `hospitalId`, plus a Firebase Auth login for it.
Neither exists on the live `dugo-plus` project yet. The seed and the account
script below create them.

Commands are in the repo root: /home/sneaky/Desktop/Code/voltron/dugo-plus

-------------------------------------------------------------------------------

STEP 1 — Get a service-account key (the one thing only you can do)
-----------------------------------------------------------------
The scripts write to Firestore with a "service account", which bypasses the
security rules. You download its key from the console:

  1. Open https://console.firebase.google.com/ and pick the `dugo-plus` project.
  2. Click the gear (Project settings) > "Service accounts" tab.
  3. Click "Generate new private key" > Generate key. A .json file downloads.
  4. Move it OUTSIDE the repo, e.g.:

       mkdir -p ~/.config/dugo-plus
       mv ~/Downloads/dugo-plus-*.json ~/.config/dugo-plus/sa-key.json

  Keep it out of the repo. Never commit it. Delete it (and revoke the key in the
  console) when you are done.

  Note: an earlier key was rotated because it leaked. The leaked key id
  `2574073f…`/`2569598b…` should be deleted in the console if it still exists.

-------------------------------------------------------------------------------

STEP 2 — Seed the facility
-----------------------------------------------------------------
Run:

  GOOGLE_APPLICATION_CREDENTIALS=~/.config/dugo-plus/sa-key.json npm run seed

This writes `hospitals/tagaytay-blood-bank` plus the other reference data
(donationTypes, systemConfig). It is re-runnable and safe: existing documents
are KEPT unless you add `--force`. It stops if no admin account exists in
`users/` (one does).

-------------------------------------------------------------------------------

STEP 3 — Create the hospital login
-----------------------------------------------------------------
Pick an email and a password for the facility (password: 8+ chars, a letter and
a digit). Then run:

  GOOGLE_APPLICATION_CREDENTIALS=~/.config/dugo-plus/sa-key.json \
    npm run create:hospital -- --email hospital@dugo.ph --password 'YourPassw0rd'

This creates:
  - a Firebase Auth user (email marked verified, so the app does not hold it at
    /verify-email), and
  - `users/{uid}` with role "hospital", the name, and
    `hospitalId: tagaytay-blood-bank`.
It is idempotent: re-running finds the existing login and re-applies the
profile. It stops if `hospitals/tagaytay-blood-bank` is missing (do Step 2) or
if the key is inside the repo.

  If it says the service account lacks a role, grant the key's service account
  "Firebase Authentication Admin" in GCP IAM (the same way roles/datastore.user
  was granted for the Worker), then re-run.

-------------------------------------------------------------------------------

STEP 4 — Delete and revoke the key
-----------------------------------------------------------------
  rm ~/.config/dugo-plus/sa-key.json
Then revoke the key in Firebase console > Project settings > Service accounts
(the key list shows created/rotated keys). No standing credential.

-------------------------------------------------------------------------------

STEP 5 — Smoke checks (browser; only you can run these)
-----------------------------------------------------------------
A) The docs/PHASES.md §6 four checks, same as any services/rules change:
   1. Sign in with email/password -> lands on /donor/profile.
   2. Reload /donor/profile -> saved values appear.
   3. Change a field, save, reload -> the change persisted.
   4. Sign in as an unverified account -> still held at /verify-email.

B) The F3 flow:
   1. Sign in as the hospital login from Step 3.
   2. You should land on /hospital/requests (not /welcome).
   3. Click "New request": choose type, component, units, urgency; Post.
   4. It returns to the list and the request is there, urgency first.
   5. Reload -> the request is still listed.
   6. Check both themes (the shell has a theme toggle in the sidebar).

-------------------------------------------------------------------------------

Troubleshooting
-----------------------------------------------------------------
- ERR_MODULE_NOT_FOUND ... index.node.mjs  -> corrupt local node_modules
  (every @firebase/* missing its .mjs builds). Fix: `npm ci` at the repo root.

- create:hospital stops on a permission error -> grant the service account
  "Firebase Authentication Admin" in GCP IAM, re-run.

- "This account is not linked to a facility yet" -> `users/{uid}.hospitalId`
  was not set; re-run Step 3 for that email.

- Request list is empty after posting -> confirm you are signed in as the
  hospital account, and that Step 2 wrote `hospitals/tagaytay-blood-bank`.

F3 Changes Summary
==================

Feature: F3 — Hospital posts and manages blood requests
Branch:  feat/f3 (cut from feat/f10, so F7 + F10a are in history)
Rows:    FR-011 (done), FR-016 (partial), FR-017 (done), FR-021 (partial),
         FR-037 (partial); FR-042/F10b deliberately not touched.

## Scope shipped

- Hospital accounts post a blood request for their facility and list the
  facility's requests, urgency first.
- "Manage" (status changes) is descoped: the update rule needs the staff custom
  claim (D15), which is not issued yet. FR-016 is `partial`.

## Files added

### Web
- layout/HospitalShell.jsx — hospital sidebar (same shell ids as AppShell, no
  admin nav, facility pill from the loaded hospital).
- pages/hospital/Requests.jsx — `/hospital/requests`: status filters (Tabs),
  urgency-first list (shared `sortRequestsByUrgency`), empty/loading/error
  states, Refresh + New request.
- pages/hospital/NewRequest.jsx — `/hospital/requests/new`: type / component /
  units / urgency, per-field validation, posts then calls `triggerMatch`.

## Files changed

### Web
- App.jsx — `/hospital/*` routes behind
  `RequireAuth > RequireVerified > RequireRole(['hospital'])`.
- services/requests.js — replaced the display fixtures with the real data layer:
  `fetchHospital`, `listHospitalRequests` (scoped to the facility, status `in`
  filter → existing `hospitalId+status+createdAt` index), `createRequest`
  (stamps denormalized name/coords, sets initial status). Kept `COMPONENTS`,
  `REQUEST_STATUSES`, `REQUEST_PRIORITIES`, `componentLabel`.
- services/users.js — `homeFor('hospital')` now returns `/hospital/requests`.
- pages/shared/Welcome.jsx — forwards a hospital session to `/hospital/requests`.
- utils/validate.js — added `validateRequest`.
- styles/app.css — hospital-area block (`.hospital-requests`, `.hospital-state`,
  `.hospital-form`, `.hospital-note`, `.hospital-form-actions`), `--d-*` tokens.

### Ops / seed
- scripts/seed-reference-data.mjs — seeds `hospitals/tagaytay-blood-bank` and,
  with `--link-email <address>`, sets that account's `users.hospitalId`.
  Owner-run (service-account key or console).
- scripts/create-hospital-account.mjs — creates the F3 hospital login when one
  does not exist: a verified Auth user plus a `role: hospital` `users/{uid}`
  with the facility's `hospitalId`. Idempotent; refuses if the facility is
  missing or the key sits inside the repo. Wired as `npm run create:hospital`.
- package.json — added the `create:hospital` script.

### Rules tests
- firestore.rules.test.mjs — blood-request cases moved to the D24 vocabulary
  (`urgent|stat|collecting`) and a `component` field; added an assert that a
  hospital-style post with the facility fields is allowed. 105 passing.

### Docs
- docs/REQUIREMENTS.md — FR-011/016/017/021/037 rows (Status, Notes, Where).
- docs/PHASES.md §2 — P2 status line; §10 — F3 manage/claims, audit deferral,
  dev-hospital seed notes.
- docs/firestore_schema.md §8 — records the dev-hospital seed.
- web/src/pages/hospital/README.md — the built Requests surface.

## Decisions

- Branch base: feat/f10 (has F7 + F10a), so `triggerMatch` and audit code exist.
- Chrome: a hospital-specific `HospitalShell` rather than reusing admin AppShell.
- Recipient: not captured — `recipientId` null, `createdBy` = posting user (D1).
- Audit: no `auditBlocks` from F3; F10b still waits on F4/F6/F8/F9.
- Schema: no field additions — schema §2.4 as written.
- Initial status: `urgent` when urgency is `urgent`, else `collecting` (D24).

F10b — Data-access audit hooks (2026-10-29)
===========================================

What landed
-----------
F10a gave the chain (`worker/src/audit.js`, `POST /audit/append`, transactional
append) and the client helper `appendAuditBlock`. F10b now emits events for the
data-access surfaces F9 built, through the deployed Worker (admin-claim):

  service / action                         eventType
  ---------------------------------------  -----------------------------------
  users.correctUserProfile                 DataAccess.Rectification
  users.updateUserStatus  -> Active        Account.Reactivated
                          -> Suspended     Account.Suspended
                          -> Removed       Account.Removed
  users.anonymiseUser                      DataAccess.Erasure
  dataRequests.updateDataRequest
     -> Completed, action Export           DataAccess.Export
     -> Completed, action Correction        DataAccess.Rectification
     -> Completed, action Deletion          DataAccess.Erasure
     -> Completed, action ''                DataAccess.Processed
     -> Rejected                            DataAccess.Rejected
  dataExport.collectUserData               DataAccess.Export

The Worker takes the actor from the caller's ID token and HMAC-hashes the entity
ref, so only `eventType` + a reference cross the wire (no raw ids/PII).

Best-effort, on purpose
-----------------------
`recordAuditEvent` (`web/src/services/audit.js`) never throws: the data action
has already happened, so a failed append is logged (`console.info('[audit]
append skipped', ...)`), not rolled back. A transactional "action + append in one
commit" needs the append inside the Cloud Function (`functions/index.js`), which
is not deployed (Blaze). Until then the chain can miss an event if the Worker is
unreachable.

     firebase deploy --only firestore:rules,firestore:indexes --project dugo-plus
3. Publish claims for the admin (the append route is admin-only):
     GOOGLE_APPLICATION_CREDENTIALS=~/.config/dugo-plus/sa-key.json npm run set:claims
4. Live smoke the chain: as an admin, open /admin/data-requests, run an export on
   a test subject, then open /admin/audit-trail and Confirm "Verify Chain" shows
   a block (DataAccess.Export) and the chain is valid.
5. Watch for `[audit] append skipped` in the browser console and `brevo send
   failed` / `matching` lines via `npx wrangler tail -c worker/wrangler.toml`.
